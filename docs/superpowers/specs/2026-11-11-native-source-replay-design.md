# Native source replay design

Date: 2026-11-11. Status: root approved implementation after independent design review, with the three guard amendments below; dispatch remains root-owned after merge/registration. Base: main `9f4abb8de6f8f20b080c59dd50f1cd64af9dc2d5`.

## Intent and choice

Close #140's external source-admission handoff gap on a fresh hosted Linux runner using the existing complete `receipt-security.py` boundary. This is a software evidence gap, independent of runtime/rights/signing/OS acceptance.

Engineer-selected approach: a **new standalone `native-security-replay.yml`** with only workflow_dispatch and a narrow Python transport helper. It preserves every existing automatic capture/caller/permission behavior. Extending registered native-security would allow earlier branch dispatch but would mix new control inputs with reusable admission gating; extending security.yml would also affect JavaScript audit orchestration. A new workflow requires reviewed PR → full CI → merge/main registration → one explicit dispatch. There is no premerge hosted replay claim or shortcut. Root controls PR/merge/dispatch. No reusable workflow_call is needed.

## Interface and boundaries

Dispatch inputs: `candidate_sha`, `source_run_id`, `source_workflow_id`, `source_artifact_id`, `source_archive_sha256`. Full lowercase commit/digest and positive numeric IDs only. Runs on ubuntu-24.04, job permissions only `contents: read`, `actions: read`; no write, secrets escalation or automatic retry. API URLs are fixed to authenticated `GITHUB_REPOSITORY`, never caller URLs. Source workflow must be native-security.yml or security.yml; security.yml must reference native-security at candidate SHA. Authenticate successful completed source run, exact workflow/run/head IDs, same source/head repository IDs+names, artifact ID/name/run/head/repository, unexpired status, API digest and independently reviewed digest. Preserve event and attempt identities.

Dispatcher `github.sha` is trusted **tool code**; historic `candidate_sha` is the **subject checkout**, recorded separately. Bootstrap exact dispatcher source via hooks-disabled Git from the fixed same-repository HTTPS origin into a fresh RUNNER_TEMP tools directory, verify HEAD; no install/build/submodule/LFS/artifact execution. Helper and unchanged receipt-security/native-admission authority run from this tools checkout. Before executing any policy, compare Git blob IDs and working-file bytes for the complete six-file authority closure in tools and candidate: scripts/native/receipt-security.py and scripts/security/{native-admission,verify-glib-closure,verify-glib-source,run-glib-controls,audit-native}.py; require equality and retain blob/SHA256 identities. Never import candidate/artifact policy. The helper provisions the exact candidate separately at allowlisted `/home/runner/work/open-film/open-film`, which must equal canonical GITHUB_WORKSPACE. Permit only an absent or empty freshly provisioned workspace, ordinary nonsymlink parents; refuse existing nonempty checkout, dirty/wrong candidate or occupied output. Never reset/delete/move an existing checkout. Original metadata must explicitly match workspace/root/GLib manifest paths before checkout/replay; it cannot choose a filesystem destination. Both Git bootstrapping and candidate checkout sanitize Git environment/config, disable hooks and configured filters/smudge/LFS, and use full nonshallow clone history. Require historical BASE73f9df9810770d52cab0cc2978e55ef8301f884e and LOCK_BLOBb4b8b94363f731001e2b42bf74778d79f725a1e4 availability and their expected path binding. This is an explicit provenance contract; current verify_admission does not git-show BASE, so no shallow-replay failure is claimed. The complete candidate closure still verifies checkout/config cleanliness and exact source modes/bytes.

Add `scripts/native/replay-security-artifact.py`: authenticated bounded download, safe extraction, original-byte payload construction, fresh checkout, existing CLI replay, entire retained-admission equality, reviewable result retention. Send GITHUB_TOKEN only to authenticated api.github.com requests. Follow archive redirects manually with HTTPS/public storage host allowlisting, no credentials/cookies cross-origin, bounded redirects/time/streamed bytes, and no token or signed URL in errors/logs. Keep the original ZIP outside the checkout. Max compressed200MiB, expanded300MiB,10000entries; API size and both ZIP hashes exact. Reject unsafe/noncanonical paths, colon/backslash, duplicate/file-parent collisions, links/special files/encryption/unsupported link extra metadata; create ordinary files exclusively without applying archive permissions. Duplicate-key JSON rejects. Select the same ten fixed raw files and six scanner stdout/stderr leaves as the existing TS bridge, verify raw scan pins; retain admission separately. Every input byte remains unchanged, including metadata IDs and float representations. Raw file8MiB/total32MiB/payload48MiB caps remain. No executable callback or archive code executes.

Invoke trusted tools `receipt-security.py` with original candidate root and payload; it offline-clones the bundle and calls unchanged complete `verify_admission`. Require process success **and entire parsed result equality** with original admission, not just status. Retain source/tool/run/artifact identities, ZIP/raw/payload/result hashes, stdout/stderr and outcome; no success marker on failure. No runtime/signer/native build is required: Python3.11+, Git and patch suffice. Six-hour freshness is unchanged: current998 artifact expires **2026-11-11T19:37:27.744045Z**. If late, fail stale; fresh capture requires a distinct authorized run/artifact, never timestamp/clock/evidence rewriting. Success records source replay only, `distributionApproved:false`.
