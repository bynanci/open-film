# M8B — optional motion candidates

User-supplied M8B specification authorizes direct implementation. Stacked base:
M8A PR #35, e78c4e06da2eb908dc0cb4548718c83b7798a8f1 (CI green, unmerged).
Latest main bb2c4521ad894478893485119442a00ffd9b34cc only adds the M7A merge
commit; M8A already contains its Named Versions implementation. No merge here.

## Contract and scope

- Reuse ProviderRegistry with motion-generation port; only explicitly labeled local
  camera fixture and external-video import are executable. Remote descriptors stay
  disabled until a separately verified trusted adapter/terms/retention/cost exists.
- Target one unlocked 2–6 second photo clip at speed 1 and optional single-image
  PhotoDepth scene bound to the same source/timing. Existing required selections
  and scene/source locks are checked by the existing solver. No new timeline.
- 2–3 fixture candidates or 1–3 explicitly selected external catalog videos.
  Per-job explicit consent; no settings/browse uploads. Receipt v1 hashes private
  prompt/negative text and binds source hash, target, provider/model, consent,
  human-review warning and output proof. Fixture is not claimed as AI generation.
- Admit bounded regular local sources; reject symlinks/playlists/URLs, oversized,
  malformed, HDR and unsupported streams. Normalize MP4 to fixed target timing,
  SDR H264/yuv420p and no audio; decode and probe actual frames. No automatic adoption.
- Preview → Accept (human/deformation review) → Import/Replace → Restore. Existing
  typed commands/edit history persist edits. Managed sources use the one catalog.
  Durable private receipts recover lost acknowledgments without duplicate mutation.
- Local Original and existing M8A Monitor frames compare with candidate video.
  Cancel/revoke clears unimported cache; late/stale results cannot become current.
  Accepted media stays available to Undo/Redo and Named Versions.
