# CI delivery reliability and browser shards implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Catch website failures before merge and reduce E2E wall time with isolated full-coverage shards.

**Architecture:** A docs build gate covers the actual published site. Four single-worker browser VMs run independently of media QA; strict discovery/result validation and the existing aggregate require every case and lane.

**Tech Stack:** Existing Node24.14, pnpm11.11, Playwright1.63, Vitest5, VitePress1.6.4 and GitHub Actions.

**Spec:** [Design](../specs/2026-10-30-ci-pages-e2e-design.md).

## Global constraints

- Keep291 browser cases, assertions, timeouts and single-worker isolation.
- No dependencies, path bypass, disabled dead-link checks or retries masking failures.
- Preserve native, format/locales/types/lint/media/build/CLI/interchange and synthetic artifacts.
- Stable release remains0.4.0; physical workstation/installer gates remain open.

## Review focus

- Missing/duplicate shard reports must fail, including cancelled matrix jobs.
- A report from a different source candidate cannot satisfy the aggregate.
- Skipped/flaky/failed tests cannot count as executed passing coverage.
- Shared ports remain isolated by VMs; test files keep their existing serial behavior.
- Internal engineering links must resolve without publishing excluded design trees.
