# M6 Audio Quality and Provider Generation Implementation Plan

Goal: add reviewable audio finishing and optional generated TTS without replacing existing editing contracts.

Base: 2af86273e0c92aab40408e86f9e4c656f85f5eaf (M3–M5 integrated; no open PRs).

Architecture: 6A measures decoded real MP4 output through FFmpeg loudnorm/astats and presents mix meters plus selected-role normalization. A private original/stem/candidate render uses the existing Renderer. Accept submits the existing volume command, leaving fade/points/ducking unchanged. The existing maximum volume of one remains; limited boosts are disclosed. Saved revision, source hashes, abort and private cache fences guard results.

6B extends ProviderRegistry with a text-to-audio port. First use is general TTS, with an explicitly labeled deterministic local tone mock and optional BYOK HTTPS adapter. Only entered text is disclosed after consent; no media is read for requests. Bounded bytes/duration, cancellation, generation/revision fencing, a source receipt and explicit preview/accept/import guard timeline insertion.

## Review focus

- Silence/nonfinite FFmpeg values never become an invented measurement or unsafe boost.
- AAC encoding peaks and concurrent source changes are measured/fenced after output.
- Locks, user automation and stale saves remain protected by existing typed edits.
- Remote error bodies, redirects and malformed audio cannot expose credentials or import unsafe bytes.
- Cancelled/late provider results cannot cross project/revision boundaries or auto-import.

Ruling: execute inline under the user's direct development/merge authorization; no additional approval handoff or worktree. Setup already has Node 24.19.0, pnpm 11.11.0, FFmpeg and Chromium. Native Cargo is unavailable locally and will be recorded separately from CI.
