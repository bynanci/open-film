# OpenFilm v0.1 Implementation Plan

> Agentic workers use independent file ownership and fresh review of integration.

**Goal:** Ship the offline folder → story → editable composition → MP4 workflow.
**Architecture:** Portable TypeScript domain and algorithms; Node media/SQLite
adapters; CLI and loopback desktop application use one service; Tauri native shell.
**Tech Stack:** Node 24, pnpm, TypeScript, Vue 3/Vite, SQLite, FFmpeg, Vitest, Tauri.
**Spec:** `docs/superpowers/specs/2026-10-05-openfilm-design.md` and `docs/PROJECT_BRIEF.md`.

## Global constraints

No original media writes or uploads. Core has no UI/filesystem imports. Template
specific words belong in `templates/proposal-film`. File paths never enter shell
command strings. Project versions are validated. No invented benchmark claims.

## Review focus

Corrupt/unsupported media must not abort a batch; unknown timestamps need explicit
uncertainty; duration locks must fail instead of silently dropping assets; project
reopening must retain selections; API and rendering must not overwrite originals.

## Independently owned tasks

- [x] Domain and SDK: implement `packages/core`, `plugin-sdk`, `analysis`; test
      schema rejection, round trip, provider consent, and template-agnostic models.
- [x] Algorithms and template: implement `metadata`, `events`, `story`, `solver`,
      `exporters`, `templates/proposal-film`; test invalid dates, timezones, exact and
      perceptual duplicates, GPS clustering, scored factors, duration infeasibility,
      chronological selection, mandatory/rejected assets, and real timeline structure.
- [x] Runtime: implement `catalog`, `media`, `render`, `application`; test actual
      SQLite and FFmpeg using generated assets, malformed-file isolation, import
      repeatability/cancellation, thumbnail/proxy generation, source hash invariance,
      story persistence, preview duration, and reopen.
- [x] Desktop: Vue content workspace, real API states and selection edits, Tauri
      shell; test accessible controls and browser create/import/story/compose/render/
      reopen flow. Native checks require an installed Rust/GTK/WebKit toolchain.
- [x] Integration: CLI and local API, package/tool configs, CI, OSS docs and ADRs;
      verify lint/typecheck/unit/integration/build/e2e, fix failures, update TASKS,
      commit and publish a reviewable GitHub branch/PR where repository permits it.

Shared exact signatures live in `docs/CONTRACTS.md`. Validate each owned subsystem
before integration, then run the whole suite and inspect actual generated output.
