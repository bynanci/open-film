# OpenFilm 0.4.0

OpenFilm 0.4.0 brings the reviewed creative-scene workflows together on one
Composition and renderer. Editing stays local-first, story-first and
non-destructive, with the existing project schema 1.0.0, Undo/Redo, autosave and
reopen behavior.

## Included workflows

- Selective local PhotoDepth with protected subjects, source/mask receipts,
  bounded arbitrary-seek parallax, fallback and typed Visual QA diagnostics.
  Foreground masks preserve transparency and stay aligned with rendered layers;
  imported Library layers work with explicit Story pools, and retiming keeps recipes valid.
- Professional still PNG, WAV and aligned audio stems, landscape/portrait/square
  profiles and review-bound crop confirmation. Mixed mono/stereo stems share one
  channel layout; delivery validates only the consumed picture/audio graph.
  Crop review binds source bytes and each actual font use, while safe process
  ownership, recovery backups and cancellation protect completed exports.
- Reviewable NLE handoff with native/metadata/baked/unsupported explanations,
  explicit opaque precomps/full mix, portable sources and verification receipts.
  Reference burn-in has a 64-selected-cue budget; larger caption sets retain
  SRT/VTT and native/manual handoff options. Review checks actual render limits
  and Story duration before approval. Ignored title placeholders stay metadata
  and do not introduce extra native picture/audio or false source-trim failures.
- Collect Media directory/ZIP packages with complete referenced-source and font
  checks, explicit rights, safe paths, stable provenance and actual reopen/render
  verification. Known credential paths reject before byte reads; supported media
  is checked by decoding its required stream, including Story-only references.
- Verified native runtime and installer-candidate tooling, owned-service lifecycle,
  signature-bound manifest bytes, permission-preserving archives and portable
  build invocation. Runtime retry retains authored drafts with project/source
  fences and explicit export/discard; pending recovery keeps close guards active.
  Local media/thumbnail playback retains strict native Origin enforcement;
  backpressured reads and failed child starts no longer strand normal close.
- Motion candidate comparison with explicit Accept/Replace/Restore, local camera
  fixtures and explicitly imported local videos. Interrupted previews no longer
  retain expired private bytes or permanently occupy preview capacity. Catalog
  adoption retries preserve accepted source identity and earlier Undo history.
  Searchable paginated video choices retain selections across pages. Receipts
  distinguish fixture, external-import and declared local-provider provenance.

## Recovery and compatibility fixes

Named Versions can explicitly delete selected snapshots to free bounded storage.
Deletion requires confirmation and a current saved revision; recovery journals
protect checkpoints. Restore rechecks target sources after checkpoint creation
and refuses to proceed if its checkpoint disappeared. Version comparison now
preserves legal composite IDs and ordering; sorted-source validation is linear.
Application, workspace and native-shell versions are aligned with this release;
snapshot software-version receipts and CLI `--version` read current package
metadata. Empty ZIP files round-trip safely; cancelling an archive waits for
owned filesystem cleanup and preserves completed outputs. Native preflight
checks all 43 audited production filter capabilities before service readiness.
Library inspection stays usable while selection/rating writes await acknowledgement,
with mutation controls and unsaved category drafts still guarded.

Original media and existing schema versions remain unchanged. Older snapshots
retain their original metadata. Source/media locks, required selection and
explicit provider consent remain authoritative.

Final review corrections keep graphics-only and gap-scene seeks exact, distinguish
mask failures from general resource limits, and leave validated caller objects
unchanged. Delivery frame rates are chosen independently of project settings;
muted clips do not block audio-only exports, dimension changes require a new crop
review, and explicit caption IDs remain distinct from automatic selection.

Native export/caption/package links use owner-bound CORS downloads while normal
browser downloads retain direct streaming. Startup cancellation and failed-close
retry retain draft and active-job close guards. Handoff captions follow renderer
frame quantization, render-required review checks title/caption pixel bounds,
and CLI handoff review/export preserves project and job-catalog bytes. Directory
collection and stem packages publish atomically without replacing existing
destinations, and the public GraphicScene schema requires complete declarative
scenes.
CLI profile exports retain the saved project revision so a completed request can
be retried across processes without an incidental timestamp write.

Singleton and low-frame-rate projects now retain their picture streams when
delivered through supported FFmpeg 6.1.1 as well as 7.1.5. Exact output-frame
bounds and picture holds are verified from decoded MP4 and first/last PNG
previews; saved project rates and original media remain unchanged.

Collect ZIP publication checks the saved revision and cancellation after archive
creation, immediately before exclusive synchronous publication. Later progress
callbacks cannot revoke committed output; existing destinations remain intact.

The development toolchain pins authenticated Vite 8.2.4 for
`GHSA-698v-4r3x-3vcv`. The actual bundled Windows editor launcher rejects
percent/line-break paths before invoking a command; normal paths retain escaping.
All other 290 package records and the pinned native lifecycle policy are retained.

## Distribution and remaining validation

This is a source release. Signed Windows/macOS installers and an automatic-update
feed are not distributed. Native bundling remains disabled by default; the
installer workflow creates manual candidates only. Linux CI and synthetic media
verification do not certify clean-machine Windows/macOS installation, physical
HDR/display appearance, sustained 4K/GPU performance, hardware listening or actual
Resolve/NLE import fidelity. The existing Linux native distribution gate for
GLib `RUSTSEC-2024-0429` remains open pending a compatible upstream remedy
and reachability review; passing advisory checks does not certify that installer.

Remote image-to-video is disabled. The deterministic local camera fixture is not
AI generation. Paid-provider terms, cost, retention and subject-detail quality
need separate review before any future remote adapter is enabled. Private photos
are never silently uploaded.

Exact candidate/merge identities, test results and synthetic FFmpeg evidence are
recorded in [release validation](../validation-stable-release.md). Apache-2.0 and
NOTICE are retained.
