# 精密編集

「編集」ワークスペースには、同じ Composition と編集履歴を使う「ストーリー」モードと「精密」モードがあります。「ストーリー」モードではビート構成、写真、全体の順序を扱います。「精密」モードは選択中の動画または音声クリップのソース時刻に集中します。モードを切り替えても別のカットは作成されません。

## ソース時刻と作品内の時刻

ソースプレビュー、波形、トランスクリプト、シーンカット、手動マーカーはすべて元ファイル内の秒数を使います。選択したクリップには Composition の開始位置、ソースのイン／アウト点、任意の再生速度があります。ソースの1秒が作品内の1秒とは限りません。速度を変更したクリップでは、選択されたソース範囲を速度に応じて変換します。UI はソース再生ヘッド、クリップ内の位置、クリップ外の位置を区別します。

ソース再生、コマ送り、波形シークで位置を探します。ズームは表示するソース範囲を変え、「再生ヘッドに追従」は表示設定です。ホバー時のプレビューはオプトインで、一時停止中にのみシークします。波形上でポインターを動かしても、再生が始まったりカットが変わったりしてはいけません。

トランスクリプトのテキストを修正すると、単語のアラインメントは `text-edited` と記録されます。セグメントへのシークは引き続き使えますが、共有スナップ機能は過去の単語データを除外します。精密編集 UI は単語単位のコントロールを使えない理由を説明します。修正したテキストによってクリップのタイミングが暗黙に変わることはありません。[トランスクリプト編集](/en/transcript-editing)を参照してください。

## トリムと分割

イン／アウトのハンドルをドラッグするか、再生ヘッド位置に端点を設定します。ドラッグ中は範囲をローカルでプレビューし、完了時に1件の編集を確定します。共有コマンド経路はソース範囲、正の長さ、再生速度、クリップロックを検証します。スナップを使うと、端点をソースマーカー、シーンカット、読み込み済み音声境界に合わせられます。[ソースマーカーとスナップ](markers-and-snapping.md)を参照してください。

選択クリップ内の再生ヘッド位置で分割すると、既存のソース範囲が2つに分かれます。両方の側に関連するソースと編集属性が残ります。分割は「ストーリー」編集と同じ Composition 履歴に属し、Undo／Redo と自動保存はその履歴を使います。元のメディアファイルを分割・変更することはありません。ロック中のクリップは再生や分析はできますが、トリムや分割の前にロック解除が必要です。

選択したタイムラインクリップがロック解除済みでも、ライブラリでソースがロックされていれば分割できません。精密編集はソースロックの理由を示し、「分割」操作と B ショートカットを無効にします。ライブラリでロックを解除してください。ソースロックはロックされていないクリップの有効なトリムを妨げません。

分割は入力側のクロスフェードが終わるまで待ちます。保護処理はクリップ速度を使ってソース範囲を変換し、共有コマンドの作品内時間に関するトランジション制約に合わせます。ソースの長さのメタデータがない場合、再生は保存済みのクリップ範囲を使えます。トリム、分割、マーカー追加、分析はアセットに有限かつ正の長さが記録されるまで待ちます。

プロジェクトの切り替えや書き出しを行う前に、エディターは保留中の作業をフラッシュする必要があります。保存に失敗または競合した場合は状態を表示し、既存のドラフト復旧処理を維持します。プロジェクトを再度開くと、別の精密編集ドラフト文書ではなく保存済みのカットを読み込みます。

## 分析とトランスクリプト

波形分析、シーン検出、文字起こしは明示的に実行し、進行状況を表示し、キャンセルできます。分析が終わるとソースの根拠情報を更新しますが、タイムラインは編集しません。読み取り専用のトランスクリプトのセグメントと単語はシーク先として使えます。長時間録音にはページ操作があります。Whisper モデルが使えなくても、ソース再生と通常の編集は利用できます。

分析の利用可否は、別のソースの作業、インポート、レンダリングなど、進行中のプロジェクト内ジョブをすべて考慮します。インスペクターは選択したソースのジョブ詳細を示し、別の作業がプロジェクトを使用中である理由を説明します。その作業が完了またはキャンセルされるまでポーリングを続け、完了後に分析を再び利用できるようにします。

マーカー操作は1ページに100行を表示し、表示範囲全体の件数と、最初／前／次／最後への移動を提供します。ページ分割で DOM の処理を減らしても、シークやスナップに必要なシーン／手動の根拠情報は破棄しません。波形のオーバーレイには別の上限があります。

精密編集ビュー内を移動してもソースプレイヤーとインスペクターを使えます。長いトランスクリプト／マーカー一覧は各領域内でスクロールし、編集コントロール全体を押し流しません。ブラウザーチェックでは英語、繁体字中国語、日本語で、対応するデスクトップサイズ 1280×720、1440×900、1920×1080 を確認します。

## キーボード操作の範囲

精密モードでは、再生に Space、コマ送りに左右、秒単位の移動に Shift+左右、分割に B、マーカーに M を使います。入力欄、選択欄、メニュー、ダイアログでの文字入力を編集ショートカットが横取りしてはいけません。また、非表示の「ストーリー」エディターで発火してはいけません。表示中のモードだけがショートカットを受け取ります。

## P0 の制限と証拠

トランスクリプトはナビゲーション用の根拠情報であり、編集可能な字幕トラックではありません。この基盤には自動ハイライト選択、顔追跡、スマートクロップ、辞書、校正、安全フレーム表示、字幕焼き込みはありません。

`tests/e2e/precision-editing.spec.ts` は Proposal 作品を使ったブラウザー受け入れテストです。写真、生成された音声付き動画、手続き型音楽を使い、実際のインポート、分析の調整、ソースシーク、スナップトリム、分割、共有履歴、再オープン、MP4 プレビューのレンダリングを確認します。ソース切り替え時のジョブ復旧、キャンセル、コマ単位の調整、有効なサブフレームトリム境界も確認します。決定的な文字起こしプロバイダーは明示的にプロトコル用フィクスチャです。実際の FFmpeg 波形／シーン処理と Whisper 推論は別の確認であり、別々に報告する必要があります。

読み取り、ジョブ、マーカー操作でメディアの変更または欠落が報告されると、ソースの根拠情報はクリアされます。精密編集／マーカー操作はソース確認に成功するまで待機します。元ファイルを戻した後はソース更新操作を使ってください。文字起こしを再実行してキャンセルした場合、以前に確認済みの結果を保持します。このソース準備チェックが、保存済み Composition や編集履歴を削除することはありません。
