# ソースマーカーとスナップ

マーカーは元のアセットとソース時刻に属します。タイムラインクリップ、複製したメディアファイル、ストーリーを変更する指示ではありません。手動マーカーはアセット ID とソースハッシュに基づいてカタログに保存します。検出したシーンマーカーはシーン結果に検出元の情報を残します。

## マーカーの動作

精密モードでは再生ヘッド位置にマーカーを追加するか、波形をダブルクリックするか、テキスト／フォームコントロール以外にフォーカスがあるときに M を押します。マーカーを選択するとソース位置へシークします。手動マーカーを削除しても、そのソースマーカーだけが削除され、クリップのトリムや元ファイルの削除は行いません。時刻はソースの長さの範囲内に収める必要があります。マーカーラベルはユーザーが入力するテキストであり、UI の言語を変えても翻訳されません。

Core マーカーの語彙には `speech`、`word`、`beat`、`chapter` も予約されています。契約に種類が定義されていても、すべてに作成 UI があるという意味ではありません。P0 で作成できるのは手動マーカーと検出済みシーンカットです。読み込み済みのトランスクリプトのセグメント／単語境界と、選択したソースクリップの端点もスナップ候補になりますが、保存済みの手動マーカーは作成しません。

## スナップの計算

`packages/analysis/src/snapping.ts` には純粋なソース時刻計算があります。ビューは現在のズーム率を使ってピクセル許容幅を秒へ変換し、有効なトリム範囲を渡します。その範囲外の候補と無効化された種類の候補は無視します。スナップをオフにすると、範囲内に制限された要求時刻を保持します。

しきい値内にある候補から最も近いものを選びます。距離が等しい場合は、優先度の高さ、時刻の早さ、候補の種類、安定した ID の順に決めるため、同じ条件で結果を再現できます。既定の優先度は次のとおりです。

| 候補                                       | 優先度 |
| ------------------------------------------ | -----: |
| 手動マーカー                               |    100 |
| クリップ端点                               |     90 |
| 検出済みシーンカット                       |     80 |
| チャプター                                 |     70 |
| ビート                                     |     60 |
| 音声またはトランスクリプトのセグメント境界 |     50 |
| 単語境界                                   |     40 |

トランスクリプトのセグメントと単語は開始・終了の両方が候補です。セグメント間の無音は自由に使えるソース時間のままです。スナップが架空の音声で埋めることはありません。トランスクリプト候補は現在読み込まれているページから取得し、そのことは UI に表示します。マーカーの可視化には別途上限があり、分析が多くても何千もの DOM 行を作りません。

## 表示と保存

スナップのフィードバックは、選ばれた対象の種類と時刻を示します。クリップを移動、並べ替え、速度変更しても、マーカーの時刻、シーンカット、トランスクリプトの時刻はソース秒のままです。スナップ後も通常のタイムラインコマンドが結果を検証します。近くのマーカーを使ってロック、ソース範囲、正の長さの制約を回避することはできません。

分析結果と手動マーカーはソースに紐付いたカタログデータです。トリムと分割は Composition の編集です。タイムラインの Undo／Redo を、一般的な分析／マーカー履歴と解釈しないでください。再度開いたときは確定済みの有効なマーカー／分析データと、独立して保存された Composition が残ります。元ソースのバイト列が変わった場合、古いソースのマーカーや分析を暗黙に再利用してはいけません。

純粋関数のテストは候補選択、しきい値、範囲、無効化項目、決定的な同点処理を確認します。精密編集のブラウザーワークフローは、製品の操作を通じて実際に保存されたマーカー、スナップトリム、共有タイムライン履歴を確認します。
