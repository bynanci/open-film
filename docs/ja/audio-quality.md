# 確認可能な音声品質（M6 / PR 6A）

AudioAutomation はすでに役割、フェード、ゲインポイント、手動ダッキングを管理しています。この機能はその契約と既存の音量コマンドを再利用します。音声 schema や2本目のタイムラインは追加せず、メディアソースを書き換えません。

アプリケーションは通常の FFmpeg Renderer を使って、非公開の MP4 を3つレンダーします。元のミックス、選択した音声ステム（他のすべてのクリップ音声をミュート）、提案ミックスです。ステムの統合ラウドネスを元に、役割別の一定音量を提案します。ナレーション／会話 −16 LUFS、音楽 −23 LUFS、環境音 −24 LUFS です。これらはワークフロー上の既定値であり、納品規格の認証ではありません。現在の音量契約は引き続き 0〜1 です。ユニティゲインを超えるブーストが必要な場合は明示的に制限します。

FFmpeg loudnorm はデコード済み入力の統合 LUFS、LRA、オーバーサンプリングしたトゥルーピークを報告します。ブロック astats はデコード後のサンプルピークと RMS／ピークのメータービンを提供します。無音と有限でない結果は null のままです。音声のないファイルや1時間を超えるファイルは明示的に失敗します。メーターはサンプル済みの出力メーターであり、リアルタイム入力メーターではありません。

候補ミックスは実際にエンコードして再測定します。フルミックスのトゥルーピークが −1 dBTP 以下でない場合、承認できません。ユーザーは元音声と候補を試聴し、その後、自動保存／履歴を通して通常の型付き音量コマンドを明示的に確定します。作成済みのフェード、カーブ、ダッキング、トリム、速度はそのままです。書き込みが不確実な場合は既存のエディター復旧ライフサイクルに従います。

結果はプロジェクト、保存済み Composition、エディターリビジョン、設定、ソースハッシュ、出力ハッシュに紐付きます。ソースのロック／拒否を尊重します。変更があると再生／承認は無効になり、サーバーとアプリケーションは古いリクエストを拒否します。クライアントの中止は子プロセスをキャンセルし、部分的なキャッシュを削除します。再試行すると新しい非公開レビューを作成します。キャッシュディレクトリはシンボリックリンクを拒否し、モード 0700 を使います。セッション内の完了済みレビューは最大5件まで保持します。パスと元メディアをプロバイダーに送信しません。

Desktop、HTTP、`openfilm audio-quality --project <path> --composition <id> --clip <id>` は同じアプリケーション境界を呼び出します。ラウドネス／ピーク値だけでは、音声明瞭度、音楽のバランス、創作上の品質は証明できません。これらは引き続き人が聴いて判断します。
