# メディアの移動と再リンク

OpenFilm は元のメディアをプロジェクトの外に保管します。.openfilm フォルダーを移動しても、カタログ、ストーリー、タイムライン、編集内容、キャッシュ済みのサムネイル／プロキシは保持されます。新しいキャッシュ参照にはプロジェクト相対パスを使います。移動したプロジェクトを開き直すと、アプリが生成した命名規則に一致する旧形式の絶対キャッシュ参照も復元します。

ファイルが見つからなくても、素材はライブラリとタイムラインに「メディアが見つかりません」と表示されたままです。評価、ロック、ソース範囲、エフェクト、ビート選択は編集して保存できます。レンダリングには元ファイルが必要です。ドライブを再接続するか、メディアを再リンクしてください。「再確認」は全メディアをデコードせず、ソースとライブラリの利用状態を更新します。利用できないライブラリには「ライブラリがオフライン」と表示されます。

フォルダーを移動した場合は「メディアを再リンク」を使い、単一ファイルにはその素材の再リンク操作を使います。新しいパスを入力するか、OS のファイル選択画面を使います。照合根拠を確認し、曖昧な候補は明示的に選んでから適用してください。再リンクの前に未保存のタイムライン編集を保存します。取り込みやレンダリングが実行中の場合は、完了するかキャンセルする必要があります。

照合は次の順に行います。

1. ファイル名が変わっていても一致する、SHA-256 内容ハッシュの完全一致。
2. 元のハッシュが不明な場合の、ライブラリ内の相対パス。
3. 元のハッシュが不明な場合の、ファイル名とバイトサイズ。
4. 識別できない旧形式のメディアに対する、単一ファイルの明示的な選択と確認。

自動選択されるのは内容が完全一致し、候補が一意の場合だけです。弱い根拠による候補は確認が必要です。ファイル名だけでソースを自動確定することはありません。既知のハッシュが一致しない場合、弱い照合で上書きすることもできません。同等の候補が複数ある場合は曖昧なまま残ります。適用時にファイルを再確認します。計画の古さ、削除済みファイル、置換メディアの尺不足、保存先の衝突は、それぞれ具体的なエラーになります。フォルダーの再リンクでは、選択したカタログ行を単一の SQLite トランザクションでまとめて更新し、失敗時は一部だけ変更しません。

ソース参照は既存の metadata["openfilm.reference"] 拡張に保存されます。内容は元 URI、ハッシュ、ファイル名、サイズ、ライブラリ ID、相対パス、論理ボリューム ID、現在のルート URI です。再リンク後も元 URI と素材 ID は維持されます。追加メタデータなので、プロジェクトとカタログのスキーマバージョンは変わりません。旧形式の参照は既存のライブラリルートとファイルシステム情報から導きます。根拠のない内容ハッシュは作りません。正常に再リンクしたソースを再取り込みしても、元の素材 ID とユーザーの判断は保たれます。

論理ボリューム ID はマウントパスやドライブ文字が変わっても維持されます。同じパスに再接続した場合は「再確認」だけで構いません。ドライブ文字やマウントポイントが変わった場合は、フォルダーを一度再リンクします。ポータブルテストでは Windows のドライブ、UNC、file URL の正規化を検査します。OS によるディスクの自動検出や、実機での Windows リムーバブルドライブ接続は、引き続きネイティブハードウェアでの検証が必要です。このリリースは物理ボリュームの自動検出を保証しません。

再リンクでソースファイルの名前変更、書き換え、削除は行いません。キャッシュメディアはプロジェクト内に残ります。元ファイルとプロジェクトの両方をバックアップしてください。
