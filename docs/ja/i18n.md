# 国際化

OpenFilm は `en-US`、`zh-TW`、`ja-JP` に対応しています。フォールバック言語は英語です。翻訳カタログとフォントはローカルに含まれ、翻訳 API、リモートフォント、テレメトリー、アカウントは必要ありません。

## UI 言語と作品の言語

UI 言語は `openfilm.uiLocale` に保存されるローカル設定です。対応済みの保存設定、ローカルワークスペースサービスから渡される OS ロケール、ブラウザー言語の順に解決し、最後に英語を使います。ロケールのファミリーは、対応する英語、繁体字中国語、日本語に対応付けます。未対応の値は次の候補へ進みます。設定を変更すると現在の UI と文書言語が即時に切り替わり、プロジェクトを再度開いたり保存したりしません。

`projectContentLocale` は独立した任意のプロジェクトフィールドで、生成するストーリーテンプレート文を制御します。新規作品では UI 言語と別に選択できます。このフィールドがない既存プロジェクトは従来の英語既定値を使い、既存テキストを書き換えません。作品名とユーザー入力の文章はコンテンツであり、UI 翻訳キーではありません。

テンプレートの beat は安定した `templateBeatKey` と、`template` または `user` を示す `titleSource`、`intentSource` を持ちます。作品言語を明示的に変更した場合、既知のテンプレート管理フィールドだけを更新します。タイトルや意図を変更するとその項目はユーザー所有になり、長さを調整する際に同じ値を送信しても所有者は変わりません。出所情報がない項目や不明なキーはそのまま保持します。テンプレートカタログは Vue に依存しない移植可能な domain コードです。

## カタログとキー

`apps/desktop/src/i18n/index.ts` が Vue I18n を登録します。`i18n/locales/` の3ファイルは、system／error カタログと app、editor、media モジュールをまとめます。キーは `errors.media.missing` のように意味を表し、英語の原文をキーにしてはいけません。Domain の状態には、翻訳済みのナビゲーションラベルではなく安定 ID を使います。

`{name}`、`{count}` などの名前付きパラメーターと、各言語の複数形を使います。数値と英語名詞を連結しないでください。`Intl.PluralRules` が複数形を選択し、`Intl.NumberFormat` と `Intl.DateTimeFormat` が数値と撮影日時を整形します。`formatDuration` は `04:32` のような安定した ASCII タイムコードを返し、必要に応じて10分の1秒を保持するため、2.5秒の静止を3秒と表示しません。呼び出し側は明示的に整数秒へ丸められます。パス、ファイル名、デバイス値、プロトコル識別子は翻訳せず、メッセージ構文として再解析もしません。

通知やエラーは表示時まで意味のある記述やオブジェクトの形で保持します。先に翻訳して文字列として保存すると、ユーザーが言語を切り替えても開いているメッセージを更新できません。

## アプリケーションエラー

`OpenFilmError` は安定した `code`、任意の文字列／数値 `params`、診断用の `detail` を持ちます。HTTP 応答は既存クライアント向けに従来の英語 `error` フィールドを残します。Desktop は `errors.<code>` を表示し、生の診断情報は技術詳細に限って公開します。不明なコードにはローカライズされた復旧メッセージを表示します。フロントエンドは英語文をパターン照合してエラー種別を推測しません。

## ロケールの追加

1. app/editor/media/system のカタログを揃え、ロケール解決処理、言語一覧、Vue メッセージを登録します。補間パラメーター名は維持してください。
2. すべての意味キーを翻訳し、用語、複数形、エラー時の操作を確認します。
3. `pnpm test:i18n`、ユニットテスト、ブラウザーのレイアウト確認を実行します。キー不足、孤立キー、空値、パラメーター不一致は失敗になります。
4. 長いタイトルや実際のファイル名を使って、ワークフロー、ダイアログ、復旧状態を確認します。UI 言語への対応だけでは作品コンテンツのロケール追加を意味しません。コンテンツには domain カタログと schema 検証も必要です。

開発用には `en-XA` もあります。パラメーターと複数形の構文を保った拡張アクセント英語で、一般文を約30〜50%長くし、短いラベルも比率に応じて広げます。正式な作品言語ではなく、本番のロケール選択には表示されません。

## テスト

`pnpm test:i18n` は各ロケールを英語と比較し、エラーコードの網羅性と Desktop のリテラル翻訳参照を確認します。ユニットテストでは解決処理、0／1／2／100の複数形、書式、pseudo 構文、エラー、コンテンツ所有権を検証します。ブラウザーテストは再読み込みなしの切り替え、保存済み設定、カスタム文章の保持、CJK と pseudo のレイアウト、ローカライズ済みの作品フローを確認します。CI ではメディアと永続化の回帰テストとともに実行します。

## リポジトリ文書と README の言語

ドキュメントサイトは Git に保存した Markdown 翻訳を使い、ブラウザーやビルド時に翻訳サービスを呼び出しません。繁体字中国語は `docs/`、英語は `docs/en/`、日本語は `docs/ja/` に置き、同じ文書を同じ相対パスで対応させます。主要な5つのユーザーガイドと、編集／書き出し関連の5ページには3言語の保存版があります。その他の技術資料は順次翻訳が必要です。

各プロジェクトの `README.md` には同じディレクトリの `README.zh-TW.md` と `README.ja.md` があり、原文にも言語リンクがあります。新しい README を追加する際は、同じ場所に両方の翻訳版も追加してください。コード、パス、識別子、コマンド、schema 値は変更しません。

`pnpm test:docs-i18n` で README の言語リンク、主要ガイド、英語参考ページとの同期を確認します。
