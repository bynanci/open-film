# MP4 圧縮品質

書き出し画面には作品に保存された実際の幅、高さ、フレームレートが表示されます。新しいプロジェクトの既定値は 1920 × 1080、30 fps です。既存プロジェクトはそのフレーム設定を維持します。プレビューの構図ガイドは出力サイズを変えません。MP4 のレンダリングは編集プロキシとは別に、読み込んだ元ソースを参照します。

書き出しで **MP4 品質** を選択します。

| 選択肢 | H.264 エンコーダー | プリセット | CRF |
| --- | --- | --- | ---: |
| 標準（既定） | libx264 | veryfast | 23 |
| 高精細 | libx264 | medium | 18 |

高精細では動画の圧縮を抑えます。書き出しに時間がかかり、ファイルは通常大きくなります。元ソースにないディテールを復元したり、以前の写真拡大を元に戻したり、HDR マスタリングを追加したり、Composition のフレームを変えたりはしません。書き出し後に拡大する処理もありません。

この選択はレンダープレビューと MP4 書き出しで共有される出力スナップショットです。変更すると既存のレンダー結果は古いものとして扱われます。出力開始時に品質を取得し、実行中のジョブではセレクターから変更できません。プロジェクト／Composition の切り替えや再起動では標準に戻ります。プロジェクト、タイムライン履歴、編集可能な NLE 出力には保存しません。既存の作品／シーン／クリップのルック、トリム、長さ、タイトルの位置、音楽トラックは変わりません。音声は既存の AAC／48 kHz レンダーパイプラインを引き続き使います。これは動画圧縮の設定であり、ロスレス音声書き出しではありません。

## ヘッドレスでの利用

```bash
pnpm cli render --project /path/film.openfilm --quality high-detail
pnpm cli export --project /path/film.openfilm --format mp4 --quality high-detail
```

`--quality` を省略すると標準を使います。不明な値や編集可能な書き出しに品質フラグを指定すると、検証エラーになります。同じ任意の `quality` フィールドはアプリケーションの `FilmRenderOptions`、HTTP `/api/render`、MP4 `/api/export` で使えます。HTTP はジョブを確保する前に検証します。値は `standard` または `high-detail` のみです。任意のコーデック、CRF 値、FFmpeg 引数は受け付けません。

非公開の `.mp4.manifest.json` にはプロファイル、実際のコーデック、プリセット、CRF、保存済みフレーム、ソース ID、出力ハッシュを記録します。レンダーを比較する場合はこのファイルを確認してください。プロファイルは既存の version-1 manifest に追加される証拠データです。

## 検証の範囲

生成テストでは x264 が実際に出力した SEI と manifest を読み取り、プロファイル間でデコードした音声を比較し、Full HD／小数フレームレートの出力を確認します。これらが示すのはソフトウェア契約であり、非公開の映像作品の主観的な品質やワークステーションの性能ベンチマークではありません。実際のカメラ／HDR、ディスプレイ、プロジェクター、ネイティブインストーラー、Resolve の確認は引き続き手動ゲートです。既存の写真モーションアダプターは拡大前に写真を再サンプリングする場合があります。この圧縮設定が、その別のサンプリング制約を解決すると主張するものではありません。

[実施済み検証](/en/validation-export-quality)を参照してください。
