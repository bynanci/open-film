# Collect Media のポータブルパッケージ

Collect Media は、保存済みのプロジェクトデータを複製し、映画を開いてレンダリングするために必要な持ち運び可能なパッケージを作成します。元ファイルを移動または書き換えることはありません。デスクトップ、HTTP、CLI は @openfilm/application の CollectMediaService を共有します。既存の Composition を唯一の編集タイムラインとして使い、プロジェクト schema 1.0.0 とカタログ schema v5 は変更しません。

## 範囲と確認

パッケージ化の前に、次のいずれかを選びます。

- 「現在の映画」は保存済み Composition とその Story を 1 つ選択します。
- 「プロジェクト全体」は保存済みのすべての Story と Composition を対象にします。

選択した Story の選択内容／制約、Composition のクリップ、セカンダリレイアウト、GraphicScene の画像が参照する資産だけを収集します。使われていないライブラリ資産は含めません。選択した Composition の音声／動画、生成 WAV、編集で使う派生メディア、その Composition に保存済みの字幕とシーンデータ、タイトル・字幕・GraphicScene の文字で解決されたフォントが対象です。

計画には各資産／フォントの表示名、種類、サイズ、SHA-256 が示されます。ファイルが見つからない、読めない、シンボリックリンク経由、カタログ確認後に変更された、サイズ上限を超えた、非対応 URI、入れ子のアーカイブ、フォント不足、明示的な権利宣言がない場合、その項目はブロックされます。代替フォントを使う場合は、パッケージ化できてもタイポグラフィ確認の警告を表示します。代替フォントが見た目も同等だという保証ではありません。

すべてのメディアファイルと収集フォントに、owned、licensed、cc0、public-domain、other のいずれかの権利根拠が必要です。自分の所有物ではない宣言ではライセンス名が必須で、帰属表示は任意です。この宣言はユーザーが提供する記録であり、自動的なライセンス判定ではありません。受領情報には絶対ローカルパスや秘密情報らしい文字列を入力できず、file URL も受け付けません。

## パッケージ構成とプライバシー

既存のカタログ書き込みを停止している間に、アプリは project.json と SQLite 整合性のあるカタログ画像を取得します。カタログには選択資産とその文字起こしデータだけを残し、ジョブ、レビュー提案、キャッシュ、未選択資産、旧形式の自由ページ残骸は削除します。公開前にフィルター済み SQLite 画像を vacuum します。Named Versions のスナップショットは意図的に除外し、UI／manifest に versionsIncluded: false と記録します。

同じバイト列のソースは一度だけ sources/<ハッシュ先頭 2 文字>/<sha256>.<拡張子> に保存します。フォントは fonts/<sha256>.<拡張子> に保存します。各資産のパッケージ URI は安定した資産 ID に対して不透明かつ一意です。openfilm.managedSource.relativePath がハッシュ名のファイルを示します。移動後に開き直すと、パッケージ内の管理対象ソースだけを再配置します。元メディアはそのままです。

manifest にはファイルのハッシュ／サイズ、選択した Story／Composition ID、資産ごとのソースハッシュ、フォント、権利宣言、対象範囲、バージョン除外、各元 URI の SHA-256 ダイジェストだけを記録します。元の絶対ソースパスは含みません。資産表示名はファイル名だけにし、パスのようなタグを除外し、秘密情報らしいメタデータキーを削除します。メタデータ文字列内のローカルパスはダイジェストに置き換えます。プロジェクトスキーマ、Composition ID、ロック、選択済みメディア ID、保存済みの編集状態は保持されます。

## 安全性、上限、公開

ディレクトリパッケージには通常ファイルのみを入れます。ZIP は UTF-8 名称と非圧縮エントリーを使います。展開時はパストラバーサル、絶対／UNC／ドライブパス、重複または大文字小文字が衝突するパス、シンボリックリンク／特殊ファイル、入れ子のアーカイブ、不正ヘッダー、重なり合うエントリー、サイズ超過、不正 CRC を拒否します。アーカイブは新しい非公開一時ディレクトリにのみ展開します。ソース、パッケージ、出力パスのシンボリックリンク要素を拒否し、ディレクトリ内のハードリンクファイルも拒否します。名前はポータブルな相対パスに正規化し、CJK 名は往復できます。

現在の実装上限は、ソース 10,000 個、1 ファイル 2 GiB、manifest 16 MiB、カタログスナップショットは既存の 256 MiB 上限です。ZIP 出力は ZIP32 の 4 GiB 未満です。展開爆弾を避けるため ZIP エントリーは圧縮しません。容量見積もりには非圧縮データと manifest を含め、ZIP ヘッダーは含めません。作業は保存先の隣で段階的に準備し、保存先ごとの排他ロックを使います。ソース、プロジェクト、カタログのリビジョン確認後に公開します。キャンセル時は一時ファイルを削除し、公開済みの不完全パッケージを残しません。既存の保存先を意図的に上書きすることはありません。

HTTP サービスは開いているプロジェクトの exports/ 内に一意の名前でのみ作成します。検証も同じディレクトリ内のパッケージ名を受け取ります。CLI はローカルコマンドで、明示的な保存先を指定できます。任意のアーカイブ展開先を指定するエンドポイントはありません。

## 検証と再オープン

Package Verify はディレクトリパッケージをコピーするか、ZIP を非公開の一時ルートに展開します。manifest の各ファイルのハッシュとサイズ、カタログ内の存在、資産 URI／再配置メタデータ、ソースとフォントのハッシュ、選択 Story／Composition ID、権利範囲を検査します。元ソースの場所にアクセスできない隔離環境でパッケージを開き、プレビューと実際の MP4 をレンダリングします。MP4 のレンダリング記録にあるソースハッシュと manifest、MP4 バイトハッシュも照合します。FFmpeg は全動画フレームをデコードし、FFprobe は H.264 の寸法、フレームレート、デコード済みフレーム数／時間、想定音声ストリームを確認します。返却される証拠はハッシュと技術的なストリーム情報のみで、ソースパスは含みません。

プロジェクト全体のパッケージでは、最初の保存済み Composition を代表する MP4 として検証します。他の Composition もパッケージに含まれ、開いた後に選べます。隔離検証で確認できるのは現在のホスト上の動作です。Windows／macOS のファイルシステム挙動、ワークステーションにインストールされたフォント、特定 NLE での動作を認定するものではありません。自動化の証拠と残る手動確認は[Collect Media の検証](/validation-collect-media)をご覧ください。

## コマンド

CLI では JSON 配列で権利宣言を明示する必要があります。一般的な手順は次のとおりです。

```sh
pnpm cli collect plan --project ./film.openfilm --scope current-film \
  --composition <composition-id> --rights ./rights.json
pnpm cli collect create --project ./film.openfilm --scope current-film \
  --composition <composition-id> --rights ./rights.json \
  --plan-id <plan-id> --base-revision <revision> \
  --format zip --destination ./handoff/film.zip
pnpm cli collect verify --project ./film.openfilm --package ./handoff/film.zip
```

HTTP ルートは POST /api/collect/plan、POST /api/collect/create、POST /api/collect/verify です。リクエストを閉じると作成／検証をキャンセルできます。サーバーは一時作業が停止するまでプロジェクトを使用中のままにします。デスクトップアプリの書き出し画面でも、同じ計画、権利確認、パッケージ作成、検証を実行できます。
