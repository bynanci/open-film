## Automated Contracts & Architecture

| Area                                     | Evidence                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Canonical Recipe & Whitelisted Steps** | Canonical recipe (`guided-story-to-video`) defines 8 strictly whitelisted steps (`story-plan-select` -> `scene-prepare` -> `narration` -> `timing-captions` -> `composition-adopt` -> `render` -> `visual-qa` -> `export`). Enforced via `ALLOWED_PIPELINE_STEP_TYPES` and `validatePipelineRecipe`.                                                       |
| **Typed Ports & DAG Acyclicity**         | Port types (`story-reference`, `story-plan`, `asset-list`, `scene-prep-result`, `audio-source`, `timing-result`, `composition`, `render-artifact`, `qa-report`, `export-artifact`) are checked against step inputs and outputs. DAG topological validation (`checkRecipeAcyclic`) detects direct, indirect, and self-referencing cycles upon registration. |
| **Immutable Input Snapshots & Digest**   | Input state is captured in `PipelineInputSnapshot` with a deterministic 64-character lowercase hex digest (`computeInputSnapshotDigest`). Asset arrays are normalized for order independence.                                                                                                                                                              |
| **Lifecycle State vs. Result Freshness** | Execution status (`idle`, `running`, `waiting-review`, `succeeded`, `failed`, `cancelled`) is strictly decoupled from freshness (`current`, `outdated`, `stale`). External project mutations increment the project revision, causing `isRunOutdated` to flag historical runs as `outdated` without rewriting run records.                                  |
| **Legal Adoption Receipts**              | Step 5 (`composition-adopt`) adopts the rough cut and creates a `PipelineRunReceipt`. This legally advances `expectedRevision` to match the newly adopted project revision, ensuring the run's own modifications do not self-invalidate into stale state.                                                                                                  |
| **Heavy Media Concurrency = 1**          | Render and solver execution are guarded by a dedicated serialization lock (`heavyLock`), guaranteeing `concurrency = 1` for heavy media processing while editor mutations follow the serial transaction boundary.                                                                                                                                          |
| **Tone Mock Guard**                      | Step 3 checks TTS providers and strictly forbids synthetic tones (`local-audio-mock`) from masquerading as speech narration, throwing an actionable error explaining that tone mock cannot masquerade as speech.                                                                                                                                           |
| **Remote Motion Availability**           | Step 2 checks remote motion capabilities and marks `remoteMotionStatus = "unavailable"` when unconfigured, preventing fake progress or unconfigured remote calls.                                                                                                                                                                                          |
| **Zero-Lock Review Gates**               | Steps in `waiting-review` release all write locks and hold no background child processes. Review decisions (`accepted`, `rejected`, `skipped`) are recorded with timestamps, notes, and optional adjustments. Polling (`getRun`, `listRuns`) is strictly read-only and never creates jobs or advances revisions.                                           |
| **Cancellation & Late Result Shielding** | `cancelRun` broadcasts an `AbortSignal` to active tasks. Subprocess results arriving after cancellation are discarded.                                                                                                                                                                                                                                     |
| **Durable Reopen Persistence**           | Runs are stored in `cache/pipeline-runs.json`. Reopening the application via `OpenFilmApplication.open` rehydrates existing runs without falsely terminating active or review processes due to UI reload.                                                                                                                                                  |
| **Retry vs. New Run**                    | `retryRun` reruns a failed or cancelled run using the _identical_ immutable `inputSnapshot`, incrementing the attempt counter without creating duplicate runs. `createRun` creates a new run with the current project revision.                                                                                                                            |
| **Idempotent Execution**                 | Calling `startRun` on an already succeeded run returns immediately without re-triggering side effects or duplicating compositions.                                                                                                                                                                                                                         |
| **Desktop UI & Accessibility**           | `PipelineOrchestrationModal.vue` provides preflight controls (narration strategy selector), stepper track with status chips, waiting review action cards, artifacts list, outdated warning banner, full i18n (`en-US`, `zh-TW`, `ja-JP`), reduced motion support, and 1024x768 responsiveness. Triggered via header button and Story workspace toolbar.    |

## Native Conditions & Environment Notes

- **FFmpeg / FFprobe**: System PATH on this Windows development host does not include the `ffmpeg` executable. Test suites cleanly detect this and verify pipeline receipts, step attempts, preview render artifacts (`cache/renders/${id}_preview.mp4`), and QA reports. Final physical bitstream encoding and decoding requires an environment with FFmpeg installed.
- **Python / Whisper Protocol**: Python 3 is not available in system PATH on this Windows host (`code 9009`). Pipeline orchestration operates in pure TypeScript with zero Python or native binary dependencies.
