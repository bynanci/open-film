# 國際化

OpenFilm 支援 `en-US`、`zh-TW` 和 `ja-JP`。英文是回退語言。翻譯目錄與字型都隨應用程式在本機提供，不需要翻譯 API、遠端字型、遙測或帳號。

## 介面語言與影片語言

介面語言是 `openfilm.uiLocale` 下的本機偏好設定。解析順序為：已儲存且受支援的偏好、本機工作區服務提供的作業系統語系、瀏覽器語言，最後使用英文。語系家族會對應到受支援的英文、繁體中文或日文；不支援的值會繼續回退。設定變更會立即更新目前介面和文件語言，不會重新開啟或儲存專案。

`projectContentLocale` 是另一個選用專案欄位，用於控制產生的故事模板文字。建立新影片時，可獨立於介面語言選擇此值。沒有此欄位的舊專案會沿用舊版英文預設值，且不會改寫既有文字。影片名稱和使用者撰寫的文字是內容，不是 UI 翻譯 key。

模板 beat 會帶有穩定的 `templateBeatKey`，以及值為 `template` 或 `user` 的 `titleSource`、`intentSource`。明確變更影片語言時，只更新已知且由模板管理的欄位。使用者修改標題或意圖後，該欄位會歸為使用者內容；若只是調整時長並送出未變動的欄位，所有權不會改變。缺少來源資訊或未知的 key 會原樣保留。模板目錄屬於可攜的 domain 程式碼，與 Vue 無關。

## 翻譯目錄與 key

`apps/desktop/src/i18n/index.ts` 會安裝 Vue I18n。`i18n/locales/` 下的三個檔案彙整系統／錯誤目錄，以及 app、editor、media 模組。Key 應描述意義，例如 `errors.media.missing`；不可把英文原句當成 key。Domain 狀態使用穩定 ID，不使用翻譯後的導覽標籤。

使用 `{name}`、`{count}` 等具名參數和各語系的複數形式。不要把數字與英文名詞直接串接。`Intl.PluralRules` 選擇複數形式；`Intl.NumberFormat` 和 `Intl.DateTimeFormat` 格式化數值與拍攝日期。`formatDuration` 會回傳穩定的 ASCII 時碼，例如 `04:32`，必要時保留十分之一秒，避免把 2.5 秒停留顯示成 3 秒。呼叫端可明確要求四捨五入到整秒。路徑、檔名、裝置值與協定識別碼不會翻譯，也不會重新解析為訊息語法。

通知和錯誤應保留語意描述或物件，直到顯示時才翻譯。若預先翻譯並儲存字串，使用者切換語言後，已開啟的訊息就無法更新。

## 應用程式錯誤

`OpenFilmError` 帶有穩定的 `code`、選用的字串／數字 `params` 和診斷資訊 `detail`。HTTP 回應保留舊版英文 `error` 欄位，供既有用戶端使用。Desktop 會顯示 `errors.<code>`，原始診斷只放在技術細節中。未知代碼會顯示本地化的復原訊息；前端程式不會比對英文句子來推斷錯誤類型。

## 新增語系

1. 新增完整的 app/editor/media/system 目錄，並註冊語系解析器、語系列表及 Vue 訊息；保留所有插值參數名稱。
2. 翻譯每個語意 key，並檢查術語、複數形式與錯誤處理動作。
3. 執行 `pnpm test:i18n`、單元測試及瀏覽器版面檢查。缺少 key、多餘 key、空值或參數不一致都會使檢查失敗。
4. 使用較長標題和真實檔名檢查完整流程、對話框與復原狀態。支援 UI 語言不代表影片內容已支援該語系；影片內容還需要 domain 目錄和 schema 驗證。

開發環境另含 `en-XA`，這是會保留參數與複數語法的擴展重音英文，用來讓一般句子長約 30–50%，短標籤則依比例增加。它不是正式支援的影片語言，正式版語系列表不會提供。

## 測試

`pnpm test:i18n` 會逐一比較各語系與英文、驗證錯誤代碼覆蓋，並檢查 Desktop 中的字面翻譯參照。單元測試涵蓋語系解析、0／1／2／100 的複數形式、格式、pseudo 語法、錯誤和內容所有權。瀏覽器測試驗證切換語言時不重新載入、儲存偏好、自訂文字不變、CJK 與 pseudo 版面，以及本地化影片流程。CI 會與媒體和持久化回歸測試一同執行。

## Repo 文件與 README 語系

文件網站使用已提交在 Git 的 Markdown 翻譯，不在瀏覽器或建置時即時呼叫翻譯服務。繁體中文頁面放在 `docs/`，英文放在 `docs/en/`，日文放在 `docs/ja/`；同一篇文件以相同路徑對應不同語系。目前五份主要使用指南，以及創意故事模板、精準剪輯、來源標記與吸附、MP4 壓縮品質和音訊品質頁面，已有三語保存版本；其他技術參考仍待逐篇補上翻譯。

每個專案的 `README.md` 都有同目錄的 `README.zh-TW.md` 和 `README.ja.md`，原始 README 也提供語言連結。新增專案 README 時，請在同一目錄補上兩個翻譯版本。翻譯時保留程式碼、路徑、識別碼、命令和 schema 值。

執行 `pnpm test:docs-i18n`，檢查 README 語言連結、主要指南及英文參考頁同步。
