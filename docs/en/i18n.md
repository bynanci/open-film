# Internationalization

OpenFilm supports `en-US`, `zh-TW` and `ja-JP`. English is the fallback. Translation
catalogs and fonts are local; no translation API, remote font, telemetry or account
is needed.

## UI language and film language

The interface language is a local preference under `openfilm.uiLocale`. Resolution
uses a supported saved preference, then the host OS locale supplied by the local
workspace service, then browser languages, then English. Locale families map to
the supported English, Traditional Chinese or Japanese variant. Unsupported values
fall through. Settings changes update the mounted interface immediately and set
the document language; they do not reopen or save the project.

`projectContentLocale` is a separate optional project field. It controls generated
story-template text. New films choose it independently from the interface language.
Projects without it use the legacy English default without rewriting existing
text. Film names and user-authored text are content, never UI translation keys.

Template beats carry a stable `templateBeatKey`, plus separate `titleSource` and
`intentSource` values of `template` or `user`. An explicit film-language change
updates only known template-owned fields. A changed title or intent becomes
user-owned; submitting an unchanged field while adjusting duration does not change
ownership. Missing provenance and unknown keys remain verbatim. Template catalogs
are portable domain code, independent of Vue.

## Catalogs and keys

`apps/desktop/src/i18n/index.ts` installs Vue I18n. The three files under
`i18n/locales/` aggregate the system/error catalog and app, editor and media modules.
Keys describe meaning, such as `errors.media.missing`; English source sentences
are never keys. Domain state uses stable IDs, not translated navigation labels.

Use named parameters, such as `{name}` or `{count}`, and locale plural choices.
Do not concatenate counts with an English noun. `Intl.PluralRules` selects forms;
`Intl.NumberFormat` and `Intl.DateTimeFormat` format numbers and capture dates.
`formatDuration` returns stable ASCII timecodes such as `04:32`, retaining tenths
when needed so a 2.5-second hold is not displayed as 3 seconds. Callers can
explicitly request whole-second rounding. Paths, filenames, device values and protocol identifiers
are never translated or reparsed as message syntax.

Keep notices and errors as semantic descriptors or objects until display time.
Translating once into a stored string prevents an open message from changing when
the user switches language.

## Application errors

`OpenFilmError` carries a stable `code`, optional string/number `params`, and
diagnostic `detail`. The HTTP response retains the legacy English `error` field
for existing clients. Desktop renders `errors.<code>` and exposes raw diagnostics
only in technical details. Unknown codes receive a localized recovery message;
frontend code never pattern-matches English prose to infer an error type.

## Adding a locale

1. Add complete app/editor/media/system catalogs and register the locale resolver,
   locale list and Vue messages. Preserve all interpolation names.
2. Translate every semantic key; review terminology, plural forms and error actions.
3. Run `pnpm test:i18n`, unit tests and browser layout checks. Missing keys, orphan
   keys, empty values and mismatched parameters fail validation.
4. Review the full workflow, dialogs and recovery states using long titles and real
   filenames. UI language support does not automatically imply a new film-content
   locale; that requires domain catalogs and schema validation too.

Development includes `en-XA`, an expanded accented version of English that keeps
parameters and plural syntax intact. It stresses labels by roughly 30–50% for
normal sentences. Very short labels gain proportionally more framing. It is not
a supported film language and is unavailable in production locale selection.

## Repository documents and README locales

The documentation site uses Markdown committed to Git and does not call a translation service at runtime or during the build. Traditional Chinese pages live under `docs/`, English references under `docs/en/`, and Japanese translations under `docs/ja/`. The main user guides are available in all three locales; architecture contracts, roadmaps, release notes and validation evidence are currently maintained mostly in English.

Use the [documentation map](index.md) when adding pages. Keep each validation record tied to its original commit, platform, tool versions, commands, results and manual gates. Do not rewrite a past record to reflect current status. Add later results as dated entries and update current status in ROADMAP.md and TASKS.md. Research notes must include sources, access dates and unverified claims.

Each project-root README.md should have README.zh-TW.md and README.ja.md beside it and link to both. Preserve code, paths, identifiers, commands, schema values, measurements and evidence links in translations. If a full translation of a technical record is not ready, add an accurate summary linking to the English source and retain its limits.

Run `pnpm test:docs-i18n` to check README links, the main guides and English reference synchronization. See [Contributing](https://github.com/bynanci/open-film/blob/main/CONTRIBUTING.md).
