## 概要

2つの Gemini レポートには、より大きなメディアライブラリの性能測定、出力ファイルの確認だけでなく編集品質も評価すること、任意で使えるローカルの画像・音声モデル、実際の NLE と Windows/macOS ワークステーションでの検証など、今後も検討する価値のある研究方向があります。これらは既存ロードマップと一部重複するため、既存項目と受け入れ記録に結び付けます。

レポート内の製品状況には修正が必要な点があります。2,000 件の上限は一度の scene-planning scope に適用され、メディアライブラリ全体の上限ではありません。Visual QA/contact sheets と PhotoDepth は現在の main に実装済みです。OTIO parser の read/write/read テストもありますが、任意の NLE から完全な編集を往復できることや、Resolve の実機検証が完了したことを示すものではありません。

このメモは研究上の示唆と検証条件を記録します。リリースの約束、技術選定、新しい重複 backlog 項目は追加しません。

## 元のスナップショット以降の main の進展

現在の main には D3A1 Sequence waveforms、D6B derived Collect delivery、および Windows issue 66～68 に対する CI 修正と browser gate がマージされています。証拠は[波形の検証](../docs/validation-sequence-waveforms.md)、[Collect の検証](../docs/validation-collect-coverage.md)、[Windows recovery の検証](../docs/validation-windows-issue-recovery.md)を参照してください。Windows CI により再現可能な OS の証拠が追加されましたが、物理 Windows 10 ワークステーション、macOS、外付けドライブ、ネイティブのインストール／更新／回復、Resolve/NLE の gate は閉じていません。

比較表では研究の追跡可能性のため、元の基準を維持しています。今後の計画には最新の roadmap、task、候補バージョンの検証結果を使い、元のスナップショットを現時点の不足一覧として扱わないでください。

## 引用論文の確認

確認日：2026-10-30。以下は共有レポートの引用が主張を裏付けるかを確認したものです。論文の結果を OpenFilm の成果として扱いません。

- [Timeline-Bench, arXiv:2609.35143](https://arxiv.org/abs/2609.35143) の概要には、実際の動画編集タスク56件、Agent 設定16種類とあります。平均解決率は14.0%、最高は26.8%、比較の83.5%で人間の編集者は参照編集を好みました。完了条件には、内容／brief の検査と、編集者のブラインド評価で調整した品質検査の両方が含まれます。これは機械的な正しさと創作品質を分けるという研究上の示唆を支持しますが、OpenFilm のモデルスコアや性能目標を示すものではありません。共有レポートの896 runs、72.9% mechanical pass、93% false success という数値は概要で確認できませんでした。利用前に論文全文と各数値の定義・分母を確認してください。
- レポートは [arXiv:2610.25649](https://arxiv.org/abs/2610.25649) を query-centric timeline と関連付けていますが、実際の題名は _InteractAgent: Agentic Human Motion Interaction with Memory-Augmented Reflection_ です。人とシーンのロボット／動作インタラクションを研究しており、動画編集タイムラインの主張を裏付けません。
- [arXiv:2610.25733](https://arxiv.org/abs/2610.25733) は確かに query-centric TimelineAgent ですが、複数文書からイベントのタイムラインを抽出する研究であり、動画編集 Agent を扱っていません。
- [arXiv:2610.26275](https://arxiv.org/abs/2610.26275) は動画内の中間的な因果イベント連鎖の生成を研究しています。物語上のイベント理解には関連しますが、評価対象は VLM の因果推論です。自動編集、タイムライン操作、完成映像の品質を検証するものではありません。

## 今後の検討に向けた確認項目

研究方向をロードマップに加える前に、既存項目を重複させず、該当する質問に回答してください。

1. **規模：** catalog 数、1回の計画 scope、並列分析のどれを測定しますか？固定 fixture、ハードウェア、メモリ／遅延指標は何ですか？
2. **創作品質：** 納品の必須条件と人による品質評価を分けていますか？ブラインド評価者、rubric、参照編集、データのライセンスは明確ですか？
3. **ローカルモデル：** インストール／削除、オフライン、権限／同意、プライバシー、ライセンス、CPU/GPU fallback を再現できますか？
4. **NLE 互換性：** parser、実際の読み込み／再生、メディア relink、書き出し／再読み込みのどれを検証しますか？効果ごとの忠実度の境界は明確ですか？
5. **ワークステーションの証拠：** テストした commit、Windows/macOS バージョン、ハードウェア、ツールのバージョン、コマンド、ログは同じ候補版に対応していますか？

バージョン番号と段階名は main のロードマップに従います。このメモでは共有レポートが提案する v0.5/v0.6/v1.0 の日程を採用しません。
