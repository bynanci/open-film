# Resolve 準備用フィクスチャとパーサー検証

[繁體中文](README.zh-TW.md) · [English](README.md) · [日本語](README.ja.md)

`verify.py` は公式 OpenTimelineIO 0.18.1、FFprobe、FFmpeg を使用します。`scripts/verify-interchange.ts` 経由で実行すると、手続き型の CC0 素材と5つの OTIO ケースを生成し、公式の読み込み／書き込み／再読み込みを行います。実際のファイル URL、ハッシュ、境界を検査し、ソース欠落時に検証が失敗することも確認します。合成ソースと Renderer が実際に出力した MP4／完全なミックス WAV もデコードし、映像と音声の同期を検査します。DaVinci Resolve のプロセスは起動も模擬もしません。

```sh
OPENFILM_OTIO_PYTHON=/path/to/otio-venv/bin/python pnpm test:interchange --output /path/to/empty/bundle
```

出力にはカットのみ、メタデータのみの高度な編集、分数フレームレートのケースと、期待する manifest／レポートが含まれます。高度な効果は手動で再作成する必要があります。スローモーションのケースは、ラベル付きのパディング間隔を意図的に示します。保持されるソースはデコード可能な合成 PNG／MP4／WAV で、検証後も元ソースのハッシュは変わりません。

追加の同期2ケースは、同じ時計を持つ映像のみの MP4 とステレオ 48 kHz PCM WAV を使用します。ソースのフレーム30を白く点滅させ、同時に50ミリ秒の1 kHz音を開始します。ソースと出力は160×90、120フレーム（4秒または4.004秒）です。トリムと配置には既存の Composition、OTIO エクスポーター、共通の有理数クロック、正規の音声サンプル時刻、FFmpegRenderer を使います。

| ケース            | フレームレート | ソース音のサンプル | トリム／配置フレーム | 出力の点滅フレーム | 出力音のサンプル |
| ----------------- | -------------- | ------------------ | -------------------- | ------------------ | ---------------- |
| `sync-30`         | 30/1           | 48000              | 12 / 24              | 42                 | 67200            |
| `sync-fractional` | 30000/1001     | 48048              | 10 / 15              | 35                 | 56056            |

Python 検証器は生成されたメタデータから計算せず、上記の期待値を独立に宣言します。公式 OTIO の2回の読み込み、ソース／出力の全フレーム、完全なステレオ PCM ミックス、音の開始／終了、総サンプル数を検査します。分数レートは絶対的な有理数位置で換算し、端点を整数サンプルに揃えています。1フレームの1601.6サンプルを毎回丸めると誤差が累積します。実測値は `sync-evidence.json` に保存します。PCM と映像のアサーションのサンプル／フレーム不確かさはゼロです。MP4 AAC は別途観測し、開始／終了に ±1024 サンプルを許容します。AAC LC の変換1フレーム分であり、振幅0.01の検出しきい値付近に生じる非可逆圧縮のプリエコー／リンギングを扱うためです。この許容幅を PCM に適用することはありません。

Resolve のインポートチェックリストとして使う前に、[NLE 互換性と手動 QA](../../../docs/nle-compatibility.md)を確認してください。このスクリプトの成功はパーサー、ソース参照、合成素材の Renderer 同期の証拠です。Resolve での実際のインポートと再生は未検証です。
